# Масштабирование и обновление кода

- Несколько Workers могут слушать одну Task Queue → горизонтальное масштабирование.
- Разные Task Queues помогают разделить потоки/нагрузку, но требуют эксплуатации.
- **Изменение логики Workflow требует совместимости с уже записанной историей.**
- Для долгоживущих процессов изучить Worker Versioning и безопасные deployments.
- Длинные истории → `Continue-As-New` при соответствующей бизнес-семантике.

# Versioning: изменение Workflow без nondeterminism

```go
v := workflow.GetVersion(ctx, "add-fraud-check", workflow.DefaultVersion, 1)
if v == 1 {
    if err := workflow.ExecuteActivity(ctx, "CheckFraud", req).Get(ctx, nil); err != nil {
        return err
    }
}
err := workflow.ExecuteActivity(ctx, "ChargePayment", req).Get(ctx, nil)
```

- Старые executions при Replay получают `DefaultVersion` → идут по старому пути.
- Новые executions записывают в историю marker с версией `1`.
- Старую ветку удаляют, когда все Workflows на ней завершились.
- Альтернатива — **Worker Versioning**: старые executions остаются на Workers со старым кодом.
- Проверка в CI: replay реальных историй через `worker.NewWorkflowReplayer()`.

Replayer позволяет выгрузить Event History из production (temporal workflow show --output json) и прогнать её через новый код в unit-тесте — самый надёжный способ поймать несовместимость до деплоя.

# Где Temporal стоит использовать, а где нет

- Многошаговые процессы с внешними side effects.

# Итог: пять правил разработки с Temporal

1. **Workflow** = бизнес-решения; **Activity** = внешний I/O.
2. Рассчитывай на **Replay** и соблюдай детерминизм.
3. Activity может выполниться повторно → **idempotency**.
4. Saga требует **явных compensations**, у которых тоже бывают ошибки.
5. Для production нужны **история + логи + метрики + tracing**.

**Финальный вопрос:** `ChargePayment` выполнился, но ответ потерялся. Какая часть системы обеспечивает безопасность повтора?

<div v-click>

> Внешний Payment API с idempotency key и бизнес-контрактом. Temporal гарантирует восстановление и повторную попытку по политике, но не атомарность внешнего side effect.

</div>
